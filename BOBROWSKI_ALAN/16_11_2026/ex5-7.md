# Exercise 5 – Organising the Test Suite

The LibraryCatalog tests are divided into four separate TestCase classes:

1. **TestAddingBooks** – Tests adding books and counting books.
2. **TestRemovingBooks** – Tests removing existing and unknown books.
3. **TestSearching** – Tests searching by author, ISBN and available books.
4. **TestBorrowing** – Tests borrowing and returning books.

Each class has its own `setUp()` method, which creates a catalogue containing three books.

### Running the tests

To run the tests in verbose mode:

```bash
python -m unittest -v test_library
```

The `-v` option displays the name of each test and whether it passed or failed.

**Observation:**

The verbose output is easier to read because each test is displayed separately. It is easier to identify which test failed.

# Exercise 6 – subTest

The `subTest()` method allows us to test multiple inputs in one test method.

### Example

```python
def test_is_even(self):
    test_cases = [
        (2, True),
        (4, True),
        (6, True),
        (8, True),
        (1, False),
        (3, False),
        (-2, True),
        (-5, False),
        (0, True)
    ]

    for number, expected in test_cases:
        with self.subTest(number=number):
            self.assertEqual(is_even(number), expected)
```

### Deliberately breaking one test

Change `(6, True)` to `(6, False)`.

The test will fail and display the input that caused the failure.

**Observation:**

The `subTest()` method identifies exactly which input failed. The remaining inputs are still tested even if one test fails.

# Exercise 7 – skip and expectedFailure

### 1. Skip a test

```python
@unittest.skip("not implemented yet")
def test_future_feature(self):
    self.assertTrue(False)
```

This test will not execute because it is marked as skipped.

### 2. Skip a test only on Windows

```python
import sys

@unittest.skipIf(sys.platform == "win32", "posix only")
def test_posix_only(self):
    self.assertTrue(True)
```

This test runs on other platforms but is skipped on Windows.

### 3. Expected failure

```python
@unittest.expectedFailure
def test_future_functionality(self):
    self.assertEqual(2 + 2, 5)
```

This test executes but is expected to fail.

### Understanding the summary

When running the test suite, the summary might look like this:

```text
Ran 25 tests in 0.005s

OK (skipped=1, expected failures=1)
```

Explanation:

- **OK:** All normal tests passed.
- **skipped=1:** One test was skipped.
- **expected failures=1:** One test failed as expected.
- **unexpected successes=1:** A test marked as expected to fail actually passed.
